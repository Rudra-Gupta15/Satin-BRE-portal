# Model Testing — Tab Field Reference

Covers the 6 tabs on the **Model Testing** page (`Page3Inference.jsx`): Transactions,
Analytics, Credit Score, Anomalies, Model Evaluation, BRE payload.

All data comes from one API call, `POST /api/inference/run`, built by
`_build_bundle()` in `BRE-backend/app/routers/inference.py`. If a bank
statement was uploaded for the selected data source, every field below is
computed for real from the parsed statement (`dataSource: "UPLOADED_STATEMENT"`).
Otherwise everything is deterministically simulated from a seed derived from
the **Custom ID** (`dataSource: "SIMULATED"`) — same Custom ID always
reproduces the same numbers, but there is no real statement behind it.

## 2. Analytics tab

`bundle.analytics` (`generate_analytics()`), one 12-month chart + table **per selected
model** — the shape of `chart`/`tableRows` differs by `modelId`.

### Common wrapper fields

| Field                                                 | Meaning                                                                                                                                                |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `modelId` / `name`                                | Which sub-model this analytics view belongs to.                                                                                                        |
| `badge`                                             | One-line status pill, e.g. "Low Risk (Approved)", "Healthy Cashflow (12.3K Net)", "Clean Account (Anomaly Index 4)", "Stable Balance (ADB ₹185,000)". |
| `metric`                                            | Headline metric string shown next to the badge (e.g. "Credit Score: 712 / 900\| PD: 3.2%").                                                            |
| `chartTitle`                                        | Chart heading, includes the deployed model version.                                                                                                    |
| `chartType`                                         | `area` or `bar` (controls which Recharts component renders).                                                                                       |
| `dataKey` / `unit` / `chartColor` / `yDomain` | Recharts plumbing — which numeric field drives the chart, its unit suffix, line/bar color, and (risk model only) a fixed 0–10 y-axis.                |
| `tableColumns`                                      | Column headers for the table below the chart (model-specific, see below).                                                                              |
| `chart`                                             | Array of 12 monthly points, fields vary by model (below).                                                                                              |
| `tableRows`                                         | Array of 12 rows, generically named`col1`..`col7` — meanings follow the `tableColumns` order for that model.                                    |

### Risk Model

- Chart fields: `month`, `PDRiskPct` (probability of default, %), `CreditScore` (300–900).
- Table columns: Month, Default Risk (PD %), Credit Score (300-900), Inflow (₹), Outflow (₹), Avg Daily Balance (ADB), Risk Grade.
- The final month is anchored to the same score as the Credit Score tab (real data) so the two tabs never disagree; earlier months are interpolated back from a lower starting point.

### Cashflow Model

- Chart fields: `month`, `NetCashflow`, `Inflow`, `Outflow` (all ₹).
- Table columns: Month, Monthly Inflow (₹), Monthly Outflow (₹), Net Cashflow (₹), Cash Runway, DSCR Coverage, Health.
- Real data: `Inflow` is walked toward the statement's actual `avg_monthly_inflow` over the 12 months. `Outflow` is simulated as 60–68% of inflow.

### Fraud Model

- Chart fields: `month`, `AnomalyIndex` (0–20, trending down over the year), `Velocity` (transactions/day, 280–520).
- Table columns: Month, Tx Volume, UPI Velocity / Day, CERSAI Check, Anomaly Score, Flagged Tx, Verdict.
- Entirely simulated (no real-data anchoring) — `AnomalyIndex` isn't derived from the uploaded statement.

### Money Balance Model

- Chart fields: `month`, `ADBScore` (average daily balance, ₹), `MinBal` (minimum balance, ₹).
- Table columns: Month, ADB (₹), Min Balance (₹), Peak Balance (₹), Volatility Index, NACH Bounces, Stability Rating.
- Real data: `ADBScore` is walked toward the statement's actual minimum balance ÷ 0.10 (i.e. treats the real minimum as ~10% of ADB) over the 12 months.

## 3. Credit Score tab (`risk_score`)

Two objects: `bundle.riskScore` and `bundle.brePayload.feature_vector`.

### `riskScore`

| Field        | Meaning                                                                                                                                                                                                                                                                       |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `score`    | Underwriting score, 300–900 (higher = better). Real data:`compute_real_credit_score()` — starts at 520 and is adjusted by DSCR, income stability, NACH bounces, cash-withdrawal ratio, negative balance, and transaction volatility. Simulated: a seeded random 480–900. |
| `grade`    | `LOW` (score ≥ 700), `MEDIUM` (≥ 550), `HIGH` (< 550) risk.                                                                                                                                                                                                           |
| `pd`       | Probability of Default %, derived as`((900 - score) / 900) * 20`, floored at 0.4%.                                                                                                                                                                                          |
| `decision` | `APPROVED` (LOW), `CONDITIONAL APPROVAL` (MEDIUM), `REJECTED` (HIGH).                                                                                                                                                                                                   |

### `feature_vector` (also reused in the BRE payload — see below)

| Field                      | Meaning                                                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `account_age_days`       | Simulated: random 90–900 days. Real data:`null` — not derivable from a single statement.                                               |
| `avg_monthly_inflow`     | Real: total credits in the statement (assumes ~1-month/statement window). Simulated: random ₹35,000–62,000.                              |
| `nach_bounce_count_90d`  | Count of transactions whose narration matches a bounce/return/dishonour/ECS-return pattern. Simulated: 1–5 if grade is HIGH, else 0.      |
| `dscr_ratio`             | Debt Service Coverage Ratio. Real:`total_credit / total_debit`, capped at 9.99. Simulated: random 1.1–2.7.                              |
| `cash_withdrawal_ratio`  | Share of total debits that are cash withdrawals (ATM/cash-withdrawal narration match). Real: computed ratio. Simulated: random 0.01–0.12. |
| `transaction_volatility` | Coefficient of variation of transaction amounts (std dev / mean). Real: computed. Simulated: random 0.8–2.4.                              |
| `minimum_balance`        | Real: lowest running balance seen in the statement. Simulated: random ₹5,000–30,000.                                                     |
| `foir_ratio`             | Fixed Obligation to Income Ratio,`(total_debit / total_credit) * 100`.                                                                   |
| `income_stability`       | 0–1 score from consistency of credit amounts (`1 - stddev/mean` of credits, clamped). Simulated: random 0.7–0.99.                      |

The page derives two lists from this data, not returned as separate API fields:

- **Positive Drivers** (client-side, `Page3Inference.jsx`): zero NACH bounces, DSCR ≥ 1.5x, income stability ≥ 85%, cash withdrawal ratio ≤ 5% — up to 3 shown.
- **Risk Monitoring Alerts** = `brePayload.negative_factors` (see BRE payload section).

## 4. Anomalies tab

`bundle.anomalies` (`generate_anomalies()`) — a subset (~30% of transactions, min 2) flagged as anomalous, ranked by score descending.

| Field                                 | Meaning                                                                                                                             |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `date` / `narration` / `amount` | Copied from the underlying transaction.                                                                                             |
| `score`                             | Anomaly risk probability, 40.0%–95.0% (seeded random — not currently derived from the real IsolationForest model's actual score). |
| `level`                             | `HIGH` if score ≥ 70%, else `MEDIUM`.                                                                                          |
| `reasons`                           | One of`UNUSUAL_AMOUNT`, `STATISTICAL_OUTLIER`, `VELOCITY_SPIKE`, `NEW_COUNTERPARTY` (randomly assigned).                    |

**Note:** unlike the Credit Score tab, this tab is *not* wired to real statement data even when one is uploaded — it always runs off the customId-seeded simulation (`generate_anomalies()` takes only `custom_id` + `transactions`, no `real_feature_vector`).

## 5. Model Evaluation tab

`bundle.evaluation` (`generate_evaluation()`) — jittered around the selected model's
catalog `baseAccuracy` (Risk 94.8%, Cashflow 92.4%, Fraud 98.9%, Money Balance 91.6%
before any live training; live-trained models use their actual CV accuracy as the base instead).

### `evalMetrics`

| Field         | Meaning                                                          |
| ------------- | ---------------------------------------------------------------- |
| `r2Score`   | Coefficient of determination, ≈`baseAccuracy ± 1%`.          |
| `mse`       | Mean Squared Error, ≈`(1 - baseAccuracy) × 0.3–0.5`.        |
| `mae`       | Mean Absolute Error, ≈`mse × 0.6–0.75`.                     |
| `precision` | Positive Predictive Value %, ≈`baseAccuracy + 0–1.5%`.       |
| `recall`    | Sensitivity / True Positive Rate %, ≈`baseAccuracy − 0–2%`. |
| `f1Score`   | Harmonic mean of precision & recall.                             |

### `cvFolds`

5 rows (`Fold 1`..`Fold 5`), each the same metrics as above with an extra small ±1% jitter per fold, plus `status` (always `PASSED`).

**Note:** clicking "Re-evaluate Cross Validation" re-seeds with a timestamp, so numbers change slightly on every re-run — it's illustrating stability, not re-running a real held-out evaluation each time (that only happens once, at training time, in `ml_trainer.py`).

## 6. BRE payload tab

`bundle.brePayload` (`generate_bre_payload()`) — the full JSON a downstream Business
Rules Engine would consume to make an underwriting decision.

| Field                                     | Meaning                                                                                                                                                                                                                                                                                                               |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `statement_id`                          | The Custom ID entered on the page.                                                                                                                                                                                                                                                                                    |
| `bank`                                  | The Bank Name entered, or`"Not Specified"`.                                                                                                                                                                                                                                                                         |
| `total_transactions`                    | Count of transactions in`bundle.transactions`.                                                                                                                                                                                                                                                                      |
| `status`                                | Always`"ANALYZED"`.                                                                                                                                                                                                                                                                                                 |
| `data_source`                           | `"UPLOADED_STATEMENT"` if a real parsed statement was used, else `"SIMULATED"`.                                                                                                                                                                                                                                   |
| `model_metadata.selected_model`         | Display name of the active model (e.g. "Risk Model").                                                                                                                                                                                                                                                                 |
| `model_metadata.version`                | Deployed version tag (e.g. "v3.4").                                                                                                                                                                                                                                                                                   |
| `model_metadata.credit_score`           | Same as`riskScore.score`.                                                                                                                                                                                                                                                                                           |
| `model_metadata.risk_grade`             | Same as`riskScore.grade`.                                                                                                                                                                                                                                                                                           |
| `model_metadata.probability_of_default` | Same as`riskScore.pd`, but expressed as a 0–1 fraction (÷100) instead of a percentage.                                                                                                                                                                                                                            |
| `feature_vector`                        | Identical object to the one described in the Credit Score section above.                                                                                                                                                                                                                                              |
| `negative_factors`                      | Human-readable strings auto-generated when a feature crosses a risk threshold: cash withdrawal ratio > 8%, transaction volatility > 1.8, minimum balance < ₹10,000, FOIR > 40%, income stability < 0.85, any NACH bounces in 90 days. This list is what renders as "Risk Monitoring Alerts" on the Credit Score tab. |

## Cross-tab consistency

Real-data mode is deliberately anchored so numbers agree across tabs:
`real_feature_vector` and `real_risk_score` (computed once in `_build_bundle()`)
are threaded into `generate_analytics()` and `generate_bre_payload()`, so the
Credit Score, Analytics, and BRE Payload tabs always describe the same
underlying applicant. The two exceptions are **Anomalies** (always simulated)
and **Model Evaluation** (always a jittered accuracy estimate, not a live
re-evaluation) — see the notes above.
